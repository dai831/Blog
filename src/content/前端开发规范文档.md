

## 1. 命名规范

###  1.1 组件命名

- 组件名称应该采用 `PascalCase`（首字母大写）命名规范。
- 组件文件名应该与组件名称保持一致。
- 对于组件的基础样式文件，使用 kebab-case（连字符分隔）命名规范。

```vue
vueCopy code// Good
<template>
  <MyComponent></MyComponent>
</template>

<script>
export default {
  name: 'MyComponent',
};
</script>

<style src="./my-component.styles.css"></style>
```



### 1.2 变量命名

- 使用 `camelCase` 命名规范命名变量和函数。
- 对于常量，使用**大写字母和下划线分隔**的命名规范。

```javascript
javascriptCopy code// Good
const myVariable = 'example';
function myFunction() { /* ... */ }
const MAX_COUNT = 10;
```



## 2. 组件规范

### 2.1 单文件组件结构

- 单文件组件应该按照 `<template>`, `<script>`, `<style>` 的顺序组织。
- **组件的 props 和 data 应该声明为函数，而不是对象**。

```vue
vueCopy code<template>
  <div>{{ message }}</div>
</template>

<script>
export default {
  props: {
      propA: {
        type: Boolean,
        default: false
      },
  },
  data() {
    return {
      message: 'Hello',
    };
  },
};
</script>

<style scoped>
/* Styles here */
</style>
```

### 2.2 组件通信

- 使用 props 进行父子组件之间的通信。
- 使用事件（`$emit`）进行子组件向父组件的通信。
- 对于非父子组件之间的通信，使用 `Vuex` 或事件总线。



## 3. 状态管理

### 3.1 使用 `Vuex`

- 使用 `Vuex` 进行应用的状态管理。
- 将组件中共享的状态提升到 `Vuex store` 中。
- 保持` Vuex store` 中的状态**单一来源**。



## 4. 路由规范

### 4.1 使用 `Vue Router`

- 使用 `Vue Router` 进行应用的路由管理。
- 路由配置应该**模块化**，每个模块应该有自己的路由文件。



## 5. 样式规范

### 5.1 使用预处理器

- 推荐使用 `SCSS` 或 LESS 进行样式预处理。
- 使用变量、混合（`mixin`）、嵌套等特性来提高样式代码的可维护性。

### 5.2 `CSSModules`

- 使用 `CSS Modules` 来避免全局污染和样式冲突。



## 6. 代码组织

### 6.1 文件组织

- 将组件、路由、状态管理等相关文件放在对应的目录中，按功能划分。

### 6.2 文件命名

- 文件名应该能够清晰表达文件的功能和内容。



## 7. 注释规范

- 注释应该清晰、简洁，并且与代码同步更新。
- 对于复杂逻辑或关键功能，添加必要的注释。



## 8. 性能优化

- 使用异步组件来延迟加载不必要的组件。
- 对于大型列表，使用虚拟滚动以减少渲染时间。
- 避免不必要的重新渲染，使用 `shouldComponentUpdate 或 Vue` 的虚拟 DOM 来优化渲染性能。



## 9. 测试

- 编写单元测试和端到端测试以确保应用的功能和性能。
- 使用 `Jest、Vue Test Utils、Cypress` 等测试工具进行测试。



## 10.项目适配

- 在开发大屏的时候写元素宽高的时候不要写 `px`,使用 `%、vh/vw、rem、em` 等单位。
