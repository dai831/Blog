# HTTP 状态码 200，但是前端没有正常拿到数据

## 一、问题现象

前端请求接口时，浏览器 `Network` 面板中显示 HTTP 状态码为 `200`，但是页面没有正常拿到数据。

常见表现：

- HTTP 状态码是 `200`
- 页面没有数据
- 接口返回内容不完整
- 前端提示 `fail`
- 大数据量接口异常，小数据量接口正常
- 后端日志显示接口已经正常返回
- 经过 Nginx 转发后，前端接收失败

------

## 二、问题原因

HTTP 状态码 `200` 只能说明请求在 HTTP 协议层面成功，不代表前端一定能拿到完整数据。

本次问题的主要原因是：

```txt
Nginx 临时目录没有权限
```

当接口返回数据量较大时，Nginx 在转发响应数据时，可能会把部分数据写入临时目录。

如果临时目录没有读写权限，就会导致响应数据转发失败或中断。

流程如下：

```txt
后端接口正常返回
        ↓
Nginx 转发响应数据
        ↓
数据量较大，需要写入临时目录
        ↓
临时目录没有权限
        ↓
响应数据中断
        ↓
前端没有正常拿到数据
```

------

## 三、重要排查命令

### 1、查看 Nginx 错误日志

```bash
tail -f /var/log/nginx/error.log
```

重点看是否有类似错误：

```txt
permission denied
open() "/var/lib/nginx/..." failed
failed to write temporary file
```

------

### 2、查看 Nginx 运行用户

```bash
ps aux | grep nginx
```

或者查看配置文件：

```bash
cat /etc/nginx/nginx.conf
```

常见用户：

```txt
nginx
www-data
```

------

## 四、解决方式

### 1、创建 Nginx 临时目录

```bash
mkdir -p /var/lib/nginx/client_body_temp
mkdir -p /var/lib/nginx/proxy_temp
mkdir -p /var/lib/nginx/fastcgi_temp
mkdir -p /var/lib/nginx/uwsgi_temp
mkdir -p /var/lib/nginx/scgi_temp
```

------

### 2、给 Nginx 临时目录授权

如果 Nginx 用户是 `nginx`：

```bash
chown -R nginx:nginx /var/lib/nginx
chmod -R 755 /var/lib/nginx
```

如果 Nginx 用户是 `www-data`：

```bash
chown -R www-data:www-data /var/lib/nginx
chmod -R 755 /var/lib/nginx
```

------

### 3、配置 Nginx 临时目录

在 `nginx.conf` 的 `http` 模块中配置：

```nginx
http {
    client_body_temp_path /var/lib/nginx/client_body_temp;
    proxy_temp_path       /var/lib/nginx/proxy_temp;
    fastcgi_temp_path     /var/lib/nginx/fastcgi_temp;
    uwsgi_temp_path       /var/lib/nginx/uwsgi_temp;
    scgi_temp_path        /var/lib/nginx/scgi_temp;

    include /etc/nginx/conf.d/*.conf;
}
```

------

### 4、检查 Nginx 配置

```bash
nginx -t
```

如果看到下面内容，说明配置正常：

```txt
nginx: the configuration file /etc/nginx/nginx.conf syntax is ok
nginx: configuration file /etc/nginx/nginx.conf test is successful
```

------

### 5、重新加载 Nginx

```bash
systemctl reload nginx
```

如果没有生效，可以重启：

```bash
systemctl restart nginx
```

------

## 五、可选优化配置

如果接口返回数据量比较大，可以增加 Nginx 缓冲配置：

```nginx
location /api/ {
    proxy_pass http://backend_server;

    proxy_buffering on;
    proxy_buffer_size 128k;
    proxy_buffers 16 256k;
    proxy_busy_buffers_size 512k;
    proxy_temp_file_write_size 512k;

    proxy_connect_timeout 60s;
    proxy_send_timeout 120s;
    proxy_read_timeout 120s;
}
```

------

## 六、临时验证方式

如果想临时判断是否是 Nginx 缓冲或临时目录问题，可以关闭缓冲测试：

```nginx
location /api/ {
    proxy_pass http://backend_server;
    proxy_buffering off;
}
```

修改后执行：

```bash
nginx -t
systemctl reload nginx
```

如果关闭缓冲后接口正常，说明问题大概率和 Nginx 缓冲、临时目录权限有关。

注意：`proxy_buffering off` 不建议长期作为最终方案，最终还是应该正确配置临时目录权限。

------

## 七、最终结论

本次问题表面上是：

```txt
HTTP 状态码 200，但是前端没有正常拿到数据
```

实际原因是：

```txt
接口返回数据量较大，Nginx 转发响应时需要写入临时目录，但是临时目录没有权限，导致响应数据中断。
```

最终解决方式：

```txt
查看 Nginx 错误日志
        ↓
确认 permission denied
        ↓
创建 Nginx 临时目录
        ↓
给 Nginx 用户授权
        ↓
配置 Nginx 临时目录
        ↓
检查 nginx -t
        ↓
reload 或 restart Nginx
```
